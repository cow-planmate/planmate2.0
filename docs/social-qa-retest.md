# 소셜 QA 수정 및 재검증 (2026-11-15)

대상: `planmate-social-qa-report.md`에서 코드로 확인한 결함. 작업 브랜치: 각 저장소 `fix/social-qa`. 머지·운영 배포는 수행하지 않음.

## 수정

- **C1**: 로그인 중 Social SSE를 구독하고, 토큰 갱신 후 재연결. 연결 복구·탭 복귀 시 메시지/대화방/요청 재조회. 서버 15초 heartbeat와 emitter 오류 정리 추가. 디코딩 실패는 메시지 본문 없이 기록.
- **C2**: 채팅 전송 트랜잭션에서 Notification Outbox 발행 추가. 알람 클릭은 해당 대화방으로 이동.
- **C3**: 입력창 `min-w-0`, 보내기 버튼 `shrink-0`. 360px 브라우저에서 버튼 x=277, 폭=36px 확인.
- **C4**: 소셜 초기 조회 중 로딩 상태 표시. 조회 실패는 0 대신 오류 상태 표시.
- **M1/M2**: 알람창의 응답할 요청에 친구 요청 포함, 인라인 수락/거절과 처리 상태 표시. 처리한 요청 알람은 같은 요청 ID·현재 수신자에 한해 읽음 처리. 다른 화면/기기에서 응답한 상태도 목록 조회 시 반영.
- **M3**: 타인 여행기 가져가기에 작성자 알람 추가. 자기 글 가져가기는 알람 제외.
- **M4**: 서버의 보낸 요청을 조회하여 검색 결과에 `요청됨` 표시.
- **M6**: 커뮤니티 수정 화면에서 작성자 확인 전 폼을 표시하지 않고, 타인 글 프리필·제출 차단.
- **M7**: 커뮤니티 댓글·좋아요 및 채팅 전송 진행 표시.
- **M8**: 상세 조회의 400/401/403/404/410 응답은 재시도하지 않음.
- 추가: 로드된 커뮤니티 댓글에 알람 앵커 이동·강조 표시, 채팅 날짜 표시, 친구 액션 대비 개선.

## 검증

- Social: 전체 테스트 11개 (채팅 이벤트/알람 발행, 인증된 SSE 응답과 heartbeat, 상태 조회 권한 포함).
- Community: 가져가기 테스트 5개 (알람 수신자·유형·이동 경로, 자기 알람 제외 포함).
- Notification: 관련 테스트 42개 (실제 PostgreSQL/Redis Testcontainers, 읽음 API 소유권·요청 ID 분리, 기존 알람 API/저장소, 새 알람 문구).
- 웹 기존 테스트 8개.
- 웹 production build.
- Chromium 360×640 모의 HTTP/SSE 브라우저 시나리오 12개: 친구 요청 수/수락/처리 상태와 읽음, 전송 버튼 위치/전송, 수신 이벤트 반영, 재연결 후 누락 메시지 조회, 초기 로딩, 보낸 요청 표시, 채팅 알람의 대화방 진입, 타인 수정 폼 차단, 404 재시도 없음. JavaScript 오류 0건.

브라우저 검증 재실행 (프런트엔드 디렉터리에서 Vite 실행 후):

```sh
npm run dev -- --host 127.0.0.1
# 다른 터미널. Playwright를 임시 위치에 설치하는 경우:
npm install --prefix /tmp/planmate-qa-browser playwright --no-audit --no-fund
PLANMATE_PLAYWRIGHT_MODULE=/tmp/planmate-qa-browser/node_modules/playwright node tests/socialQa.browser.cjs
```

Chrome 기본 경로는 `/usr/bin/google-chrome`. 필요하면 `PLANMATE_QA_CHROME`로 지정.

## 범위와 배포 순서

운영 두 계정 재현과 실제 Kafka→브라우저 전체 경로는 이번 로컬 검증에 포함하지 않음. C1의 운영 원인은 아직 단정할 수 없으며 배포 후 실제 연결에서 재검증 필요. 서버 SSE 테스트는 Redis 전달을 모의하며, 브라우저 역시 모의 HTTP/SSE를 사용함.

알람 유형 13(`FEED_FORKED`)을 proto 소스에 추가. 현재 고정된 SDK가 이 값을 아직 포함하지 않아 기존 채팅 유형 12처럼 protobuf wire value를 사용하며 소비 서비스도 함께 지원함. **Notification을 먼저 배포한 뒤 Social/Community, 마지막으로 웹을 배포**해야 함. DB 마이그레이션은 추가하지 않음.

친구 삭제 후 대화 유지, 중복 가져가기 카운트, 답글 깊이 등 정책은 변경하지 않음. 보낸 요청 취소, 댓글 여러 줄 입력, 메시지 삭제·신고 UI, 전체 confirm 교체 등 추가 기능은 이번 수정에 포함하지 않음. 댓글 앵커는 현재 로드된 페이지 내 댓글에 적용되며 다른 페이지 댓글 자동 탐색은 미구현.
