# 재검증 보고서 대응

## 판정

사용자 재검증에서 C2/C3/M2/M5/M6/M8의 개선이 확인됐다. M3와 신규 제목 폭 회귀는 완료로 취급하지 않는다.

C1은 사용자 확인 결과 **직접 편집용 빈 시간표 생성 유지**가 요구사항이다. 자동 장소 채우기나 실패 플랜 삭제를 추가하지 않는다. 생성 버튼 아래에 빈 시간표가 열린다는 안내를 추가한다.

## 이번 변경

- N1: 숨은 span 폭 측정과 8px 최소 폭 상태를 제거하고 제목 입력이 사용 가능한 너비를 차지하게 변경. 비동기 로드/글꼴 측정 시점에 따라 한 글자 폭으로 굳는 경로 제거.
- M3 대화 보존: localStorage.userId가 없는 기존 세션에서도 access token의 sub를 UI 저장소 키로 사용. JWT 서명/권한 검증은 서버에 그대로 남는다.
- M3 라우팅: API/401 재시도/토큰 갱신/스키마 요청에 credentials: include를 적용해 ingress route 쿠키 유지. 별도 deploy PR의 Backend-v2 Service ClientIP affinity와 함께 적용하는 수정안이다. raw 세션의 파드 로컬 조회 계약은 유지하며 STOMP 허용은 추가하지 않는다.
- N2: 연결 단절 중 날짜 탭은 읽기 용도로 허용. 제목/일정 변경 및 날짜·시간 설정은 계속 차단해 미전송 편집을 방지.
- M4: 편집기의 사용법/체크리스트/AI 트리거를 모바일 상단 도구줄에 배치. 자동 사용법 말풍선은 모바일에서 숨기고, 하단 탭은 콘텐츠 흐름에 포함. 고정 높이 계산과 빈 모바일 스페이서 제거.
- M1: 대중교통 결과가 없고 자동차 경로가 있으면 자동차를 기본 표시하고 사유 안내. 사용자가 직접 선택한 모드는 덮어쓰지 않음. 대중교통 제공자 인증 문제 자체를 해결한 것은 아님.
- N3 일부: 구조화된 CHATBOT_001/002 오류를 보존하여 AI 일시 오류가 서비스 전체 연결 장애 토스트로 바뀌지 않게 처리. AI 서버 오류의 근본 원인은 별도 확인 대상.
- N4: 모바일에서 드래그만 끈 카드에 draggable의 aria-disabled/role을 전파하지 않도록 수정. 실제 추가 버튼은 계속 동작하고 빈 시간 부족은 기존 토스트로 안내.

## 검증

- `node --experimental-vm-modules --test tests/*.test.mjs`: 11개 통과. API/401 route cookie, typed AI 오류와 일반 서버 장애 구분, protobuf Join·편집·재연결, raw-only 설정, 최근 일정 정리 포함.
- 로컬 Chrome 앱/API 모킹: 비동기 제목 로드 후 1920px에서 입력 폭 300px 이상, 360/390px 도구 트리거가 타임라인을 덮지 않음, 자동 말풍선 미표시, 가로 넘침 없음, 하단 탭이 뷰포트 안에 위치.
- 연결 단절 후 2일차 탭 선택 가능 및 AI 대화창 유지 확인.
- localStorage.userId 없이 JWT sub만 있는 세션에서 새로고침 후 대화/미리보기 복원, 재연결 반영, 타 계정 격리 확인.
- 경로 fixture: 대중교통 실패 시 자동차 선택과 안내, 사용자가 대중교통을 직접 선택하면 해당 선택 유지 확인.
- 운영 읽기 확인: 현재 번들 `/assets/index-77644211.js`에는 '1분 이상' 안내와 대화 저장 코드가 있고 '최대 40초'는 없음. 보고서의 문구와 다르므로 재검증 시 번들/탭 갱신 여부를 기록해야 함.
- 운영 브라우저의 credentialed 스키마 조회: HTTP 200 및 route 쿠키 저장 확인.
- 배포 Service 변경은 server dry-run 통과. 운영 Service는 아직 변경하지 않음.

## 남은 검증

두 파드 구성에서 같은 브라우저의 raw 세션과 AI 반영이 같은 백엔드로 전달되는지는 인프라 수정 적용 후 실제 로그인 세션으로 검증해야 한다. 이 단계 전에는 M3를 해결로 닫지 않는다. iframe/타사 쿠키 차단 환경과 Gateway 교체에 따른 재연결은 별도 제약이다.

M1 제공자 인증, N3 실제 AI 서버 오류, N5 핀과 장소의 대응은 추가 근거가 필요하다. 지도 overlay DOM의 버튼 순서만으로 핀 번호 오류를 확정할 수 없다. 개인정보 문구/기본 공유 정책 등은 임의 변경하지 않는다.
